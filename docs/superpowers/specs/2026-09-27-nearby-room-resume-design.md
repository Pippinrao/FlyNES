# 联机房间：当前游戏与继续

2026-09-27 用户确认交互及布局样稿。补充现行 2026-09-23 设计及 9 月 25 日修订。

## 已批准的交互

- 任一端从游戏返回联机房间，暂停双方并保留本局进度、游戏、连接和座位。
- 任一端明确点击“继续游戏”，解除本局的双方暂停并恢复原进度。
- 房主可“更换游戏”，客机不显示此操作。打开选择页保留当前局；实际选择新游戏才结束旧局，取消选择可回房间继续。
- 断开连接仍是独立明确的操作。普通离开房间不等于断开。

## 已批准的布局

左侧约四分之一展示真实连接状态及 P1/P2；中间展示当前游戏的方块卡片，使用本机游戏大厅已有的保存截图、标题及同一配色；右侧显示暂停状态、“继续游戏”和房主专属“更换游戏”。未选游戏时房主显示“选择游戏”，客机等待。没有截图则沿用游戏大厅的标题占位。

截图按当前游戏 canonical ID 从 AndroidCoverRepository、Harmony CoverStore、iOS GameCoverModel 读取，保持原图比例；不读取 ROM 制作占位封面，不传输截图或 ROM。样稿及真实示例截图仅保存在 ignored 的 out/device-20260927/nearby-room-design.html。

## 实现与验证边界

原 return_lobby 会销毁本局，仅用于明确换游戏。回房间改用暂停与原生页面导航。原按端归属的暂停 API 保持语义，新增明确的继续本局 API，允许用户从任一端解除双方暂停；应用后台生命周期仍使用原暂停 API。共享协议增加此显式操作，当前配对测试需两端同时更新。

覆盖 host→guest 与 guest→host 恢复、帧号单调继续、会话 ID 与游戏摘要不变、双端暂停时恢复、换游戏仍可进行。三端覆盖横屏短高/宽屏、字体放大、无截图/有截图和空房间。Android/Harmony 真机验证本局恢复、截图、角色和输入；iOS 构建及模拟器证据单独记录，不能冒充 iOS 真机验收。
