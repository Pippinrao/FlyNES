# G1 模拟器性能诊断预算（本轮固定）

原计划要求先提交原生数据与数值预算，再测 Flutter 候选。以下针对固定 SDK、debug 模式、同一任务模拟器和同一底层实现的 **软件回归诊断**；不改变已有原生首卡 200ms 门槛，也不把模拟器诊断通过写成三端 G1 或发布性能通过。

当前配对原生依据为 `eaafd7d0 / 3.0.5`，两端各完成2次预热、12次正式冷启动和65秒实际游戏并新增AUTO。[Android完整数据](2026-09-29-android-native-paired-baseline.md)：可交互P95为进程后2301ms、Activity请求后1623ms；native-ready进程后2675ms；游戏PSS P95 144316KiB，核心回调P95 62.5844ms、保存窗口最大64.0871ms、软件输入P95 56.8125ms，观察到欠载增量0但保存附近有播放头重置。[Harmony完整数据](2026-09-29-ohos-native-performance.md)：请求→主按钮P95 1598ms、首卡1616ms；65.231秒实际模拟运行，游戏PSS P95 153646KiB；源/显示增长观测P95 23/43ms、保存上下文最大61/66ms、软件输入P95 34ms、欠载591次。以下数值由这些原生数据代入预先提出的公式；冻结时尚未采集候选，后续结果单列且不回改阈值。

历史 `c0511d69` Android am-start 批次导航是BUILTIN（7卡，底层2231行），首卡P95 396ms仍不满足200ms。新配对批次统一ALL/空搜索，并保留/恢复原导航；Android实际2231条、Harmony投影7条。不同入口和不同平台的数据分别记录，绝不直接相减。

## 内存超限后的定向诊断

既定debug候选实测PSS P95 335645KiB，大于275388KiB，保持FAIL。20次往返ART GC后5→20增长73728B、游戏owner/audio/timer无残留，只证明这些已观测对象，不排除Dart/native/graphics成本。

在任何Release运行采集前，确定补充方案：同一3.0.5 Release主包、本地兼容测试签名、同设备/ROM/60秒自动保存/相近历史规模，先native后Flutter各65秒。PSS仍以该模式native P95+128MiB作诊断参照；只定位构建模式相关开销，不回改上表debug预算，不把Release结果覆盖debug失败或作为真机认证。测试报告必须从实际目标包读取debuggable标志，不能沿用硬编码debug标签。Release启动12次和完整功能套件不因这项内存风险扩展重跑。

随后Harmony同样记录debug PSS P95 350956KB，大于284718KB。该端也采用相同的定向Release对照原则；必须先证明目标实际为AOT/Release原生库，测试模块不替换主库，才能采集。不能仅凭HAR名称或一个debug标志声称整体Release。若现有生产宿主无法用测试入口进入Release共享页，记录具体限制，不修改生产入口权限来绕过。
